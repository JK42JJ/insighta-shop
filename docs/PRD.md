## 1. 배경 (Background)

스마트스토어 + 도매꾹 위탁판매(드롭쉬핑) 모델로 단일 운영자가 셀러 비즈니스를 운영하려 한다. 이 모델의 구조적 약점은 명확하다.

- **마진이 얇다** (보통 10~25%) → 반품 1건이 여러 건의 이익을 상쇄한다.
- **같은 상품을 다수가 동일하게 판매** → 상품 자체로는 차별화가 안 된다.
- **반복 운영 업무가 시간을 잠식** → 상품등록, 발주, 송장 입력, 1차 CS.
- **법적 책임은 전적으로 판매자에게 있다** → 구매대행이라도 면책되지 않으며, 전자상거래법(청약철회 7일 등) 위반 시 시정조치·과태료 대상.

핵심 가설: **반복 업무를 자동화하고, 콘텐츠(상세페이지·이미지) 품질로 차별화하면**, 1인 운영자도 다수 SKU를 안정적으로 운영하며 레드오션에서 생존할 수 있다.

## 2. 목표 / 비목표 (Goals / Non-Goals)

### 2.1 목표

- **G1.** 상품 리서치(트렌드·계절성·경쟁률·마진)를 한 화면에서 의사결정 가능하게 한다.
- **G2.** 상세페이지 카피와 시나리오/모델 이미지를 AI로 생성해 등록 리드타임을 단축한다 (목표: 상품 1건 등록 준비 시간 ≤ 15분).
- **G3.** 주문 → 발주 → 송장 동기화를 자동화해 수기 입력을 제거한다.
- **G4.** 정형 CS(배송조회·교환반품·관부가세·재고문의)의 1차 응대를 자동화한다 (목표: 정형 문의 자동 처리율 ≥ 60%).
- **G5.** 전자상거래법·KC·규제 카테고리·PII(개인통관고유부호)를 시스템 차원의 가드레일로 강제한다.

### 2.2 비목표 (이번 버전에서 다루지 않음)

- 자체 물류/직접 배송 (공급사·배대지가 발송; 시스템은 송장만 동기화).
- 사입(재고 매입) 관리 — 위탁/대행에 집중.
- 쿠팡·11번가 등 멀티채널 (V2 확장 후보).
- 완전 무인 CS (복잡/클레임 건은 항상 사람에게 에스컬레이션).
- 외부 판매용 SaaS화 (V2 이후 별도 검토).

## 3. 사용자 & 페르소나 (Users)

| 페르소나 | 설명 | 핵심 니즈 |
|---|---|---|
| **운영자 (Primary)** | 1인 셀러, 본인 | 적은 시간으로 많은 SKU 운영, 손익 가시성, 법적 리스크 회피 |
| **고객 (Secondary)** | 스마트스토어 구매자 | 정확한 상품정보, 빠른 배송조회/CS 응답, 정상적인 교환·환불 |
| **공급사 (External)** | 도매꾹 등 위탁 공급처 | 정확한 발주 정보 수신 |

## 4. 사용자 스토리 (User Stories)

- US-1. 운영자로서, 데이터랩 트렌드와 경쟁 상품 수, 예상 마진을 한 화면에서 보고 등록 여부를 결정하고 싶다.
- US-2. 운영자로서, 상품 정보를 입력하면 상세페이지 카피와 시나리오 이미지 초안이 자동 생성되어 검수만 하면 되게 하고 싶다.
- US-3. 운영자로서, 주문이 들어오면 공급사 발주와 채널 송장 입력이 자동으로 끝나 있길 바란다.
- US-4. 운영자로서, "배송 언제 와요?" 같은 반복 문의는 자동 응답되고, 진짜 처리할 클레임만 내 받은편지함에 남길 원한다.
- US-5. 운영자로서, "반품 불가" 같은 위법 문구가 상세/CS에 들어가지 않도록 시스템이 막아주길 바란다.
- US-6. 고객으로서, 주문번호로 배송 상태를 즉시 안내받고 싶다.

## 6. 비기능 요구사항 (Non-Functional)

- **신뢰성:** 주문 수집/발주 파이프라인은 멱등(idempotent)·재시도 가능해야 한다. 주문 누락 0건이 목표.
- **정확성:** 가격·재고 동기화 지연 ≤ 10분. 품절 상품 노출 시간 최소화.
- **보안/컴플라이언스:** PII는 봉투암호화(MVP: 앱 레벨 AES-GCM, V1: KMS 전환), 최소 권한 접근, 목적 달성 후 파기. 개인정보보호법·전자상거래법 준수.
- **비용:** AI 호출은 분류=저비용 모델, 생성=중간 모델로 라우팅 + 프롬프트 캐싱/배치로 비용 최소화. 인프라는 1인 운영 규모에 맞는 최소 구성(단일 호스트 + Postgres)에서 시작 (상세는 디자인 독).
- **관측성:** 모든 외부 발송(메일/발주/상품등록)은 로그·추적 가능.
- **확장성:** 단일 운영자 → 멀티 스토어로 무중단 확장 가능한 데이터 모델. 인프라 컴포넌트는 어댑터 뒤에 두어 규모 증가 시 관리형 서비스(SQS/Redis/KMS)로 교체 가능해야 한다.

## 8. 범위 & 단계 (Scope & Phasing)

- **MVP (4~6주):** M1(F1.1~1.3,1.6), M2(F2.1,2.2,2.4,2.6), M3(F3.1~3.4), M4(F4.1~4.3), M5(F5.1~5.4), M6(F6.1~6.3). 단일 스마트스토어 + 도매꾹, 반자동 허용.
- **V1 (이후 4~6주):** 완전 자동화, 신뢰도 스코어, 계절성 알림, 손익 대시보드, CS 리포트.
- **V2 (탐색):** 멀티채널(쿠팡), 멀티 스토어, 해외구매대행 풀 지원(통관/합산과세), SaaS화 검토.

## 9. 리스크 & 가정 (Risks & Assumptions)

| 리스크 | 영향 | 완화 |
|---|---|---|
| 도매꾹 발주 API 미공개/제한 | 자동화 불가 | API 확인 우선, 미지원 시 연동툴(스피드고/플레이오토) 또는 반자동 RPA |
| 스마트스토어 API 정책·심사 | 등록/동기화 차단 | 커머스 API 이용 신청·심사 절차 선반영 |
| AI 생성물 저작권·초상권 | 법적 리스크 | 실인물·유명인 금지, 생성/허락된 이미지만 사용 |
| 자동 CS의 법적 오안내 | 과태료·분쟁 | 법적 문구 검증 게이트(F5.4) 필수, 클레임은 사람 처리 |
| 합산과세·통관 변동 | 마진/클레임 | 관세청·UNIPASS 기준 거래 전 확인, 마진 선반영 |

> 본 문서는 운영 설계 기준이며, 실제 세무·통관·계약은 세무사·관세사·변호사 자문을 전제로 한다.
